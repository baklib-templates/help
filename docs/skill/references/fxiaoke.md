# 纷享销客：按业务模块进入的客户帮助中心

观察日期：2026-10-19。来源包括本轮真实浏览器观察与官方页面正文；下述视觉事实来自桌面观察，未观察移动端。本文提炼可复用的设计意图，不表示客户当前站点采用本地某个模板版本，也不授权复制其品牌、素材或业务内容。

## 事实：信息架构与页面表现

首页先呈现搜索，再展示业务模块。模块入口同时给出名称和少量下一层链接，使访客可以直接进入具体任务。分类层级同时表达产品模块、使用阶段和用户角色；这些层级不能压缩成一串彼此无关的文章。

桌面首页为白色页头，右侧有官网导航。蓝色渐变首屏使用居中白色标题、宽搜索框和热门词。下方是三列无边框模块入口，每项包含线描彩色图标、名称、三个子链接及查看更多入口。

分类和文章页面都有左侧深层目录树。分类页右侧以两列图标和标题呈现入口；文章页有面包屑、中央正文及右侧页内目录。目录树解决跨文章定位，页内目录解决当前长文定位，两者用途不同。

长篇问答仍采用文章结构。不能因为内容含问答，就把首页改成 `index.faqs` 变体，或把长篇原文压成首页短答案。

## 推断：可复用的设计意图

该站的主要入口是“找到业务模块，再选择角色或任务”。搜索承接已经知道问题的用户；首页子链接缩短熟悉用户的访问路径；深树帮助用户在复杂内容体系中保留上下文。可复用的是这种多层查找关系，而非业务名称、文章内容或图标本身。

适用于模块较多、同一模块同时有用户指南与管理员指南的客户帮助中心。用户虽然阅读操作文档，首要目的仍可能是解决具体问题，不能仅凭“产品文档”改选 Docs。

## 布局处方

客户明确要求接近本案例的模块入口及目录阅读时，推荐以下组合：

| 配置 | 推荐值 | 原因 |
| --- | --- | --- |
| 首页变体（`index_style`） | `index.help_center` | 分类卡片能显示三个子链接，最接近业务模块入口 |
| `article_layout` | `tree` | 明确保留跨文章目录；这是对 `index.help_center` 自动 `reader` 的有意覆盖 |
| `category_layout` | `cards` | 承接分类中的图标、标题与分组入口 |

首页变体在建站时通过 `index_style` 选择，不是 `configure_site` 可写字段。客户要求“先选择独立产品线”时仍用 `index.help_center`，把产品线做成真实一级知识分类；若要求各层都用卡片，再显式设置 `category_layout=cards`。

这是一份针对参考案例的处方。客户只要求内页自动搭配且没有要求偏离默认时，应保持 `auto`，不能为了套用案例而擅自固定布局。

## 现有能力与差距

| 目标 | 新版 Help 当前能力 | 落地方式或边界 |
| --- | --- | --- |
| 模块卡片与三个子链接 | `index.help_center` 已有 | 从真实知识目录生成，不在模板中写死客户模块 |
| 左目录、正文、右侧 TOC | `tree` 已有这一阅读骨架 | 当前目录列出顶层主题及当前父级、同级、子页，**不是任意深度的递归展开树**；完整深树需候选定制 |
| 两列分类入口 | `cards` 已有 | 具体图标、摘要由对应页面设置提供 |
| 无边框模块、蓝渐变首屏、居中标题 | 现有默认视觉不完全相同 | 需在组织候选中调整样式；切换枚举不等于完成视觉复刻 |
| 热门搜索词 | 现有首屏快捷链接指向分类 | 不能把分类快捷链接说成搜索词；若需要独立关键词配置，应补充 schema 与模板 |
| 品牌图标与官网入口 | 支持品牌和单个自定义页头入口 | 只使用客户提供或授权素材、正式网址，不沿用参考站资源 |

`configure_site` 可以配置阅读/分类布局字段和 manifest 允许的品牌、页头、支持字段；首页变体由建站时的 `index_style` 选择，不属于可写设置。首页的 `hero_title`、`hero_description`、精选内容等由 `seed_content(path: "/", fields: ...)` 配置；路径须从 `read_page` 获取。

普通页的标题与正文由知识库维护。当前 Agent 的 `seed_content` **不支持**为普通页写 `description`、`icon_image`、`icon_name`、`reading_layout`、`related_pages` 等展示字段。即使 schema 声明了这些字段，也不能宣称 AI 已写入；应通过页面设置完成，或另行实现受支持的写入能力。内容必须来自客户原文或已读取资料，不复制本案例文章充当客户内容。

本地 `themes/wiki/wiki/templates/page.liquid` 可辅助理解目录与正文分工；新版对应实现为 `templates/page.liquid`、`snippets/_home_category_card.liquid` 和 `snippets/_reading_navigation.liquid`。这些源码仅证明模板能力，不证明线上版本归属。

## 移动适配建议：尚未观察

- 将桌面三列入口按宽度收为两列或单列，保留高频子链接，并检查长标题换行。
- 将左目录收进可展开的主题导航；页内目录使用独立的展开入口，避免两套导航占满首屏。
- 搜索框适应窄屏，热门词允许换行；不要横向挤压输入区。
- 真机或窄视口检查：从首页进入三级分类、返回父级、定位正文标题、搜索无结果、键盘焦点和深色模式。

以上是建议与验收项，不是已确认的客户移动端行为。

## 适用边界与验收

适合需要模块、角色与任务多维查找的帮助中心。仅有少量问答时无需引入复杂深树；以按章节系统学习为主要目标时再评估 Docs。

交付时分别验收首页入口、至少两层分类、长操作文章和长问答文章。确认路径真实、无权限内容不可见、目录与面包屑一致；逐项区分已配置的基础能力与仍需定制的视觉、热门词和递归树。参考站的热线、服务时间及业务承诺不自动成为客户站配置。
