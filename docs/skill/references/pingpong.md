# PingPong：搜索与任务入口结合的自助帮助中心

## 事实：信息架构与页面表现

首页将搜索、常见搜索、任务分类和常见问题组合呈现。任务入口覆盖新手、账户、收款、合规及增值服务；平台收款分类继续按电商平台和开发者平台划分。它既服务明确提问，也允许用户先找到业务阶段或所用平台。

桌面首页采用浅冰蓝渐变首屏、居中标题、胶囊搜索框与常见搜索词块。下方为白色圆角、带阴影的任务卡片，使用 3D 图标；在本轮约 1280 像素视口下，五张任务卡呈四加一排列。随后是带箭头的常见问题列表、简洁页脚，以及右下角 AI 入口。这个排列是该次视口观察，不能推定所有桌面宽度都如此。

分类页左侧为目录树，右侧为单列项目列表。本次收款卡号申请文章样本中，可见左侧目录树和宽正文，未见右侧 TOC；不能把本地模板支持 TOC 当成该文章已显示 TOC 的证据。文章提供面包屑、反馈、前后篇及相关问题，内页页头增加搜索入口。

首页常见搜索是搜索入口，常见问题列表是文章入口，任务卡片是分类入口。三者在跳转目的上不同，不应统一成看起来相似但行为不明的卡片。

## 推断：可复用的设计意图

此案例适合“用户知道问题就搜索，不知道术语就按任务进入”的自助服务。常见问题缩短重复咨询的查找路径，平台分类保留操作环境，文章中的相关问题与前后篇帮助继续完成任务。

首页有多个业务入口，不等于需要 `products`。这些入口主要是账户与服务任务，首先应按查找行为和内容关系判断。

## 布局处方

客户明确要求接近本案例时，推荐：

| 配置 | 推荐值 | 原因 |
| --- | --- | --- |
| 首页变体（`index_style`） | `index.help_center` | 搜索为主要入口，任务分类与 FAQ 补充浏览路径 |
| `article_layout` | `tree` | 分类、文章都需要目录上下文；这是对该变体自动 `reader` 的显式覆盖 |
| `category_layout` | `list` | 多层平台分类以紧凑单列选择为主 |

目标组合是 `index.help_center + tree/list`。客户要求自动搭配时，实际写入 `auto/auto`（派生 reader + cards），并说明与参考站目录阅读的差异；不要把推导出的显示结果误写成必须固定的设置。已有明确全站设置或页级覆盖须先核对，不因参考案例而静默替换。

首页只因存在 FAQ，不应切换成 `index.faqs`；只有客户明确要求让短答案成为首页主体，才使用该变体。右下角 AI 是辅助入口，也不是选择 `index.support` 的依据。

## 现有能力与差距

| 目标 | 新版 Help 当前能力 | 落地方式或边界 |
| --- | --- | --- |
| 搜索、任务分类、问答入口 | 基础组件已具备 | `show_faqs` 与真实 `faq_source` 可在首页配置；短答案与纯文章链接的呈现仍须按要求核对 |
| 独立常见搜索词块 | 没有对应关键词字段 | 当前首屏快捷链接是分类链接，不能冒充搜索词；需候选 schema 与模板扩展 |
| 左树与正文 | `tree` 有基本骨架，也可按正文标题生成 TOC | 当前为顶层及当前父级、同级、子页的上下文导航，不是完整递归深树；复杂平台目录需定制。右侧 TOC 可作为长文建议，不能声称本次文章样本已显示 |
| 3D 图标任务卡及四加一排列 | 支持页面图标素材，但默认网格和卡片比例不同 | 需客户授权素材、页面图标设置及候选样式，不能只切换 `search` 就宣称相同 |
| 反馈、前后篇、相关问题 | 已有 | 前后篇依赖实际页面顺序；相关问题需 `related_pages` 的真实站内路径和显示开关 |
| 固定右下角 AI 助手 | 现有搜索页可承载平台 AI 搜索 | `enable_ai_search` 不会凭空创建可用 AI，也不生成悬浮聊天助手；该入口需平台配置与候选交互定制 |
| 登录、注册及语言切换 | 依赖真实身份系统与站点语言方案 | 不能复用 PingPong 登录网址，也不能用静态语言按钮冒充多语言站点 |

`configure_site` 可以写全站布局、品牌、允许的显示开关及真实支持入口。首页标题、描述、精选路径、FAQ 源可用 `seed_content(path: "/", fields: ...)` 配置；先通过 `read_page` 取得当前站点路径，不能沿用本案例 hash 路径。

普通页 `icon_image`、`icon_name`、`description`、`reading_layout`、`related_pages` 等展示字段当前**不能通过 Agent 的知识库 `seed_content` 写入**。例如打开 `show_related_articles` 并不等于每篇文章已经配置关联问题；页面图标和关联路径须通过页面设置完成，或另行提供受支持的写入能力。正文只写客户提供的原文，不生成收款规则、到账时效或合规承诺。

## 本地源码辅证

本地 `themes/wiki/pingpong_wiki/templates/index.help_center.liquid` 明确组合搜索、热门词、栏目、专题和 FAQ；`templates/page.liquid` 区分子页列表与文章正文，并提供左树和 TOC。其 `snippets/_page.liquid` 还提供反馈、前后篇和人工配置的关联问题。这些能解释设计意图，但不能证明线上站点当前使用本地同一提交。

新版对应实现为 `snippets/_home_hero.liquid`、`snippets/_home_faqs.liquid`、`snippets/_reading_navigation.liquid` 和 `snippets/_related_articles.liquid`。不要将旧模板字段名、Alpine 交互或静态品牌链接直接加入新版作为兼容分支；需要的能力应在候选中按新版结构实现。

## 移动适配建议：尚未观察

- 五张任务卡在窄屏选择清晰的单列或两列布局，不强行保持桌面的四加一；验证最后一张的顺序与尺寸。
- 搜索词块允许换行，长问题标题完整可读，箭头不挤占主要文字。
- 左目录收为可展开入口；如果长文另外增加页内 TOC，采用独立的展开入口。进入文章后仍能返回当前平台分类。
- 若新增悬浮 AI，检查它不遮挡反馈按钮、输入法和页脚，并验证关闭、键盘焦点、流式失败及普通搜索回退。
- 核对登录、语言入口及内页搜索在窄屏的可发现性。

这些均为适配建议，不是已验证的客户移动端行为。

## 适用边界与验收

适合具有多业务任务、多操作平台和重复咨询的自助帮助中心。若首要任务是直接联系人工，再考虑 `support`；若只需少量独立主题阅读，可以降低目录复杂度。

验收首页三类入口的跳转行为、平台分类、真实文章、搜索、反馈、前后篇和关联问题。AI 只在后端配置可用时验收，不能仅凭图标存在宣布可用。Help 承载知识与入口，不提供账户开立、资金查询、收付款、审核或工单处理后端；参考站的业务事实和承诺不适用于其他客户。
