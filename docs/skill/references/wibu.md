# WIBU：搜索、精选知识与排错阅读

观察日期：2026-10-19。来源包括本轮真实浏览器观察与官方页面正文；视觉事实来自桌面观察，未观察移动端。本文用于理解设计意图，不证明客户当前线上绑定本地某个模板版本，也不授权使用其品牌、团队照片、文章或产品承诺。

## 事实：信息架构与页面表现

站点同时承载产品认知、使用指南和故障排查。首页不是把全部产品平均铺开，而是用搜索及经过选择的主题、文章引导访问。产品分类和帮助分类分别组织不同任务，部分文章还连接官网试用或联系入口。

桌面页头为白底、多项导航。首屏采用深蓝灰调的团队照片，白色大标题左对齐，并有橙色短划强调。宽白搜索框跨在首屏底缘，带阴影。随后是四个白色大卡片，包含青绿色图标、标题和摘要；下方另有两组精选文字列表。

分类页为灰白背景，使用橙色短划、大标题和单列白色栏目列表。排错文章没有左侧目录树，采用白色阅读板、大标题、作者日期、摘要以及右侧页内目录；链接为青绿色，橙色用于强调。

排错文章中的分步结构与产品文章中的试用链接是不同内容任务。不能据产品介绍页存在，就把整个帮助中心判定为产品卡片首页。

## 推断：可复用的设计意图

此案例强调“直接搜索问题，或从精选知识开始”，进入文章后减少跨栏目导航的干扰。分类只承担继续选择，长文章通过摘要和页内目录降低阅读成本。产品介绍与排错知识可以共享品牌，但应保留各自的内容目的。

适合技术支持、安装部署、工具使用与产品知识并存的帮助站。精选内容应由客户实际资料与运营选择决定，不能把参考站推荐排序当成新客户的高频需求。

## 布局处方

客户明确要求接近本案例时，推荐：

| 配置 | 推荐值 | 原因 |
| --- | --- | --- |
| 首页变体（`index_style`） | `index.help_center` | 搜索为显著入口，同时承接主题卡片和精选内容 |
| `article_layout` | `reader` | 该案例文章无左树；与自动搭配一致，显式写入可防止后续被覆盖 |
| `category_layout` | `list` | 分类以单列选择为主，避免让每层都变成大卡片 |

首页变体在建站时通过 `index_style` 选择，不是 `configure_site` 可写字段。客户只要求“自动搭配”时保持 `auto`；客户明确要求参考本例的单列分类，才配置 `list` 并说明原因。不要为了保留右侧 TOC 而改用带左树的 `tree`。

`index.faqs` 适合首页就地阅读简短答案的场景，`index.support` 适合服务入口优先的场景，两者都不是本案例的默认判断。原 `products` 枚举已并入帮助中心变体，不再可单独选择。

## 现有能力与差距

| 目标 | 新版 Help 当前能力 | 落地方式或边界 |
| --- | --- | --- |
| 搜索、主题入口、精选内容 | 已有基础组件 | `featured_pages` 使用本站真实路径；当前首页只提供一组精选配置 |
| 两组独立精选文字列表 | 没有对应的两组独立配置 | 若客户需要分别维护，应新增候选 schema 与渲染组件，不能重复一组数据冒充 |
| 无左树的阅读正文 | `reader` 已有 | 默认 TOC 是正文上方的原生展开区域，**不是桌面右侧 TOC**；右侧形式需候选定制 |
| 单列分类 | `category_layout=list` 已有 | 分类标题、正文和子页来自知识库及页面设置 |
| 作者、日期 | 有全站显示开关 | 只展示实际作者与日期，不生成虚构身份或更新时间 |
| 照片背景、左对齐白标题、跨底缘搜索 | 当前首屏不能仅靠设置完整表达 | `hero_image` 当前呈现旁侧配图，不是全幅背景；须在候选中调整结构和样式 |
| 青绿链接与橙色强调 | 可使用平台品牌色体系 | 精确双强调色、照片遮罩及局部样式需候选设计验证，不写死参考站品牌 |
| 四个大主题卡 | 能呈现分类卡片 | 精确列数、卡片比例、摘要长度与图标需按实际内容调整，不能由布局枚举保证复刻 |

`configure_site` 可写 manifest 允许的全站布局、品牌、作者日期开关等字段。首页标题、描述、图片和精选路径可用现有首页写入接口配置；图片须来自客户授权素材或 DAM 正式引用，不能直接复用参考站团队照片。

普通页的 `description`、图标、`reading_layout`、`related_pages` 等虽有 schema，当前 Agent 的知识库 `seed_content` **不写这些展示字段**。文章摘要若要出现在专门的摘要区，应通过页面设置完成；不得宣称把正文第一段写入就等同于设置了摘要。普通文章正文仍通过知识库原文写入和同步。

本地 `themes/wiki/wiki` 的分类与文章组件可辅助理解内容模型；新版实现可查 `snippets/_home_hero.liquid`、`snippets/_home_featured.liquid`、`templates/page.liquid`。源码仅为能力辅证，不能推定 WIBU 的线上版本。

## 移动适配建议：尚未观察

- 四张卡片根据内容收为两列或单列，避免摘要被截断后失去区分意义。
- 将跨首屏底缘的搜索在窄屏改为稳定的正常文档流，检查阴影和照片遮罩的可读性。
- 右侧 TOC 在窄屏收为文章上方的可展开目录；不能恢复一棵未被客户要求的左侧深树。
- 验证页头多导航的收起方式、单列分类点击区域、长表格与步骤图片、搜索和反馈键盘操作。

这些是适配建议，不代表已经观察或验收客户的移动端。

## 适用边界与验收

适合以查找与排错为主、兼顾产品知识的支持站。若客户需要长期跨章节学习或复杂交叉导航，应重新评估阅读布局，不机械坚持无左树。

验收至少包含首页、单列分类、一篇长排错文和一篇产品介绍。检查正文、摘要、作者日期和 TOC 各自来源；核对试用及联系链接为客户真实系统。帮助模板不提供授权签发、软件下载分发后台或客服工单系统，也不继承参考站的技术、性能与服务承诺。
