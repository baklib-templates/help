# RingConn：产品支持与服务支持分流

观察日期：2026-10-19。来源为官方支持站页面文本与同日桌面浏览器验收；未找到明确对应的本地客户主题。本次截图索引：`tmp/help-customer-design-20261019/screenshots/` 下的 `ringconn-home.jpg`、`ringconn-product.jpg`、`ringconn-downloads.jpg`。浏览器已点击产品页 Downloads 标签，确认切换为两张 PDF 卡；不据此推定其他所有标签及移动端均已验收。

## 已观察的界面与页面链

[首页](https://support.ringconn.com/)采用黑色页头、白色品牌标志，浅色产品主视觉区域中居中放置黑色标题和白色搜索。下方依次是三张大产品图卡、六项服务支持卡和四种联系渠道。型号包括 Gen 3、Gen 2、Gen 2 Air；服务内容包含选码、换购、保障与运输、退换货等入口，部分链接进入品牌主站。

实际页面链为[产品支持目录](https://support.ringconn.com/product-support) → [Gen 3 支持页](https://support.ringconn.com/product-support/gen3)，也有 [Gen 2](https://support.ringconn.com/product-support/gen2) 与 [Gen 2 Air](https://support.ringconn.com/product-support/gen2air) 的独立支持页。跨产品服务另有[产品保障说明](https://support.ringconn.com/general-faqs)。

Gen 3 页使用大幅产品横幅、面包屑、型号标题和 Shop Now 链接，下面设置 FAQ、Downloads、Specs、Videos 标签。FAQ 按选购、保养、连接、充电等问题组组织，问题可展开；Downloads 切换后展示两份 PDF。产品页把同一型号的不同内容形式放在一起，首页服务区则承接跨型号任务。

## 可复用处方

适合少量主力型号、型号差异需要清楚表达的消费硬件品牌。首页首先确定产品范围；产品页把问题、文件、规格与视频集中呈现；退换货、运输、保障等服务任务保持独立。图卡用于识别产品，不能仅用装饰图片替代型号名称。

可借鉴黑色品牌页头与浅色主体的分层、大产品图卡、产品内分组和服务分流。购买按钮只有在客户明确需要且提供真实 URL 时才加入；帮助中心不因此成为商城，也不复制案例的销售、健康或保障承诺。

## 现有 Help 配置与候选定制边界

| 需求 | 现有能力与实施边界 |
| --- | --- |
| 产品选择首页 | 选 `index.help_center` 变体，由真实一级知识分类承载产品卡片，产品下组织指南或问题。接近本案例的宽正文时推荐显式 `article_layout=reader`；若客户要求自动搭配则保持 `auto`（该变体派生 reader + cards）。这些配置不等于型号页已有四个内容标签；精确的三产品大卡需候选定制。 |
| 产品与服务分别成区 | 现有首页可利用真实分类、精选路径和支持入口形成基础。精确的三产品大卡、六服务卡独立区域，以及混合站内/外部服务卡，需要候选增加明确的数据与展示配置。 |
| 分组折叠 FAQ | 当前 FAQ 分类布局可展示真实子页的问题摘要与展开内容；完整的产品范围、问题分组及多标签联合交互需要候选定制。不能把空分类当答案，不能只切换到 `index.faqs` 变体就声称完成产品详情页。 |
| PDF、规格和视频标签 | 必须有真实文件、规格内容及视频来源，再定义模块与引用。当前普通页没有现成的多标签产品数据模型，也没有保证 AI 能上传 PDF、填充下载卡或自动组装视频列表的工具契约。 |
| 产品照片与产品横幅 | 首页可配置正式 DAM 引用的 `hero_image`；普通页 `icon_image` 由页面设置配置，不能宣称已通过当前 `seed_content` 写入。型号横幅和大图卡比例仍需候选定制。 |
| 黑页头、四联系渠道、购买链接 | 品牌基础设置可复用，具体色彩与版式需候选实现。当前只有一个 `support_url` 加邮箱、电话；聊天和表单同时独立展示需要新增清楚的数据配置。购买、工单及订单功能只能链接到客户已有系统。 |

普通页 `description`、`icon_image`、`icon_name`、`reading_layout`、`tags`、`video_url`、`related_pages` 均受当前页面设置/工具边界约束，不能因 manifest 列出了字段就认为知识库 Agent 已能写入。保留来源正文与权限，在固定版本的组织候选内实现超出配置的结构，预览真实内容后验收。

## 移动适配建议（本次未实测）

- 页头压缩为品牌与可展开导航，搜索继续可见；产品横幅采用适合窄屏的裁切，不压住型号文字。
- 产品和服务卡改为单列或两列，优先呈现名称与用途；避免为了保持桌面布局而缩小文字。
- 产品标签允许横向滚动并清楚标记当前项，键盘与辅助技术也能操作；切换时保持型号上下文。
- FAQ 按组浏览，展开区保持可读行宽；文件卡纵向排列并显示真实文件名称，视频保留比例。
- 求助入口紧随相关内容，购买按钮不遮挡查找答案和联系支持的主任务。

## 适用范围与命名需求示例

适用于少量型号、强调产品识别且需要自助售后的品牌。安装步骤极多、维修树很深时，可优先采用 Procolored 式机型树；只有少量任务且无需选型号时，不必增加产品选择层。

客户说“参考 RingConn，先选型号，型号页能切换问题、手册、参数和视频”时，提取为“产品优先首页＋产品内多内容模块＋独立服务入口”。先选定 `index.help_center` 变体并把型号做成真实一级分类，明确四标签和服务区属于候选定制，并索取真实媒体与文件。客户只说“像 RingConn 的视觉”时，不擅自添加 Shop Now、商城流程或服务保障政策。
